# 模拟内核 v0.2（口碑 + 动态定价已接入）

目标：把规则文档里的模拟循环完整跑起来，验证「能不能转」。数值精度后续 hotfix。

内核按分层拆在同目录的模块里，`simulate.py` 只是兼容门面：

```
config → util → model → products → market → settle → ai → goals → game → report
```

只允许左边被右边 import；改代码请直接改对应模块，不要往 `simulate.py` 里加逻辑。

## 运行

```bash
python selftest.py                                  # 58 条验收自测，应先跑这个
python simulate.py --days 720 --ai 50 --cash 3000    # 基准场景
python simulate.py --days 360 --ai 12 --cash 1500    # 小规模快速验证
```

参数：`--days` 天数、`--ai` 对手数、`--cash` 每家起始资金（¥M）、`--seed` 随机种子。
输出：控制台快照 + `run_report.md`。

## 目标模式（FR-1101 / FR-1102 / FR-1103）

`Game.configure_mode("goals")` 把对局切到目标模式：从当前日算起 3600 天（10×360）为期限，
逐日追踪四个目标，全部达成提前结算，否则到期结算；破产为失败。评级按达成个数
4/3/2/1/0 → A/B/C/D/E，0 个不计分。

- 市值进前三：存活公司日排名曾 ≤ 3（`rank_score` 即快照 `market_cap`）。
- 区域霸主：航线最近结算日客流按航段端点区域均摊，任一区域份额曾 ≥ 35%。
- 高质高效：月报 EBITDA 率 ≥ 15% 且客流加权准点率 ≥ 85%，连续 24 个月。
- 网络扩张：日航段数 ≥ 100 且客流加权平均客座率 ≥ 75%。

旧的 `evaluate_goals()` 只用于 `run_report.md` 的终局快照，不含逐日追踪；
交互对局以 `Game._update_goals()` 的 `goals_snapshot()` 为准。

## 一个游戏日发生了什么

```
机龄 +1/360 天                    口碑的长期分化来源
  ↓
AI 决策（每 7 日）
  ├─ 关停 LF < 0.40 的航线
  ├─ 票价：以目标载客率 0.82 为锚的比例控制器
  ├─ 高 LF 航线加班次（不足则买机）
  └─ 从 HUB / 已服务城市延伸开新线
  ↓
update_route_stats()              准点率、取消率、口碑目标值（含惯性 5%/日）
  ↓
build_products()                  航线 → 行程产品；机队周转超限的航线本日不执行
  ↓
cabin_demand()                    能级池 → 方式分担 → 三舱拆分
  ↓
logit 分配                        价格 / 时间 / 班次 / 口碑 / HUB / 经停 / 换机
  ↓
段容量 yield 截断                  跨越航段的旅客挤占短途客
  ↓
settle_day()                      收入 − 9 项成本
  ↓
LF / 客流加权口碑 / 破产 / 市值
```

## 本轮新增（v0.2）

### 1. 口碑机制（R-616 / R-617）

```
on_time      = clamp(0.985 − 0.005·机龄, 0.80, 0.99)
cancel_rate  = clamp(0.005 + 0.003·max(0, 机龄−12), 0, 0.12)
comfort_w    = 10 + 20 · clamp((航距−1500)/5000, 0, 1)      # 关键：随航距放大
rep_target   = 50 + 25·准点分 + 10·机龄分 + comfort_w·舒适度 + 5·HUB覆盖 − 15·取消率
rep_route   += (rep_target − rep_route) · 0.05              # 惯性
rep_company  = Σ(rep_route · 该航线客流) / Σ客流            # 客流加权
```

**为什么 `comfort_w` 要随距离放大**：按文档原式（固定 10 分权重），机型舒适度只影响约 3 个口碑点，
在 logit 里折算出的效用差约 0.05，几乎不可见。改成随航距升到 30 分后，低舒适度机型执飞 6,000 km
以上航线的口碑损失约 11 点 → 份额差约 20%，「长航线自然淘汰不舒适机型」才真正成立。

### 2. 动态定价（AI）：比利润，不比载客率

**不设载客率目标，允许售罄。** AI 对每条航线枚举 8 档涨价倍数（0.90–1.40），用 logit 的单选项
替换恒等式预测每档下的客流，再比较两种策略的利润：

```
某选项效用变化 Δ 后：s' = s·e^Δ / (1 − s + s·e^Δ)，   Δ = −c_price · ln(涨价倍数)
利润 = (票价 × 倍数 − 单位变动成本) × min(需求 × s', 座位数)
取利润最大的倍数
```

于是同一条航线上会出现两种合理结局：
- **需求弹性大**（份额低）→ 涨价掉客太快 → 宁可低价卖满；
- **座位是瓶颈**（已售罄）→ 涨价后仍卖得满 → 涨价纯增利润。

实测票价落在 `0.87–1.36 × 参考价`，52% 航线售罄、12% 航线 LF < 60%——这正是「两种策略并存」。

首版用「LF>0.90 涨价 / LF<0.55 降价」的双阈值，实测形成**棘轮**：缺运力时涨上去，运力跟上后
跌不回来。第二版用「目标载客率 0.82」的比例控制器，结果变成了替 AI 做决定。第三版才改成现在的
利润比较——它自己会决定要不要涨价。

### 3. 机龄推进

每架飞机每日 `age += 1/360`，使准点率、取消率、维护成本、口碑都随时间恶化，
这是三种成本（新机 → 贵但口碑好 / 旧机 → 便宜但掉口碑）之间权衡的来源。

### 4. 破产与收缩

| 机制 | 触发条件 | 动作 |
|---|---|---|
| 被动关线 | 连续 2 个决策周期载客率 < 0.40 | 关掉该航线（**保留最后一条**，防止变成无收入僵尸） |
| 强制收缩 | 连续 60 天 EBITDA < 0 | 砍最差航线 + 卖一架最旧的飞机（按市价 85% 回笼现金） |
| 暂停扩张 | 连续 30 天 EBITDA < 0 | 不再开新线、不再买机 |
| 资金链断裂 | 现金 < 0 且无新增贷款能力 | 破产清算 |
| 资不抵债 | 负债 > 3 × 权益 | 破产清算 |
| 清算 | 破产时 | 航线与时刻回公共池，机队按 70% 二手市价流入市场（R-910） |

**过程中修掉一个致命 bug**：`borrow_capacity()` 里对 12 个月 EBITDA 取了 `abs()`，
导致**亏损航司反而获得更高授信额度**，于是永远不会破产。改为 `max(0, EBITDA)` 后淘汰才开始发生。

**第二个结构性发现：AI 原本从不借钱扩张**（买飞机必须付现），所以永远不会过度扩张、
也就永远不会失败。加入「允许 50% 债务融资买机」后，破产才成为真实可能性。

至此 `--cost-mult` 就是难度旋钮：

| 成本系数 | 破产 | 收缩次数 | 全网 EBITDA 率 |
|---|---|---|---|
| 1.0 | 1 / 50 | 3 | 27% |
| **1.2（默认）** | **2 / 50** | **22** | **15.3%** |
| 1.3 | 6 / 50 | 111 | 11% |
| 2.5（压力测试） | 49 / 50 | 833 | 全行业亏损 |

## 基准场景结果（50 家 × 720 日 × 起始 3,000 ¥M × 成本系数 1.0）

| 指标 | 参数轮后 | 上一版 | 合理区间 | 判断 |
|---|---|---|---|---|
| 存活公司 | **49 / 50** | 50 / 50 | 45–48 | ⚠ 基准难度仍几乎无淘汰 |
| 全网平均载客率 | **87.4%** | 93.3% | 75–90% | ✅ |
| EBITDA 率 | **14.5%** | 14.3% | 15–25% | ⚠ 略低于下限 |
| 经停航线 | **33 条（4%，全部 2 段）** | 31 条 | — | ✅ |
| 航线条数 / 机队 | 769 / 513 | 663 / 482 | — | ✅ |
| 日客流 | 182,894 | 182,391 | — | ✅ |
| 日收入 / 成本 / EBITDA | 374.0 / 344.8 / 54.1 ¥M | 407.7 / 383.8 / 58.3 | — | ✅ |

**难度旋钮 `--cost-mult`**（实测，360 日）：

| 系数 | 破产 | 说明 |
|---|---|---|
| 1.0（默认） | 0 / 50 | 玩家满负荷经营可盈亏平衡 |
| 1.2 | 0 / 50 | 玩家需要更好的航线与定价 |
| 1.35 | 1 / 50 | 开始出现淘汰 |

参数轮后基准难度对 AI 仍偏松（AI 普遍盈利）；设计意图是让**小规模玩家**能活下来，
难度主要来自与 50 家 AI 抢市场，而不是被固定成本压死。要提高难度用 `--cost-mult 1.2+`。

## 本轮修掉的漏洞

| 编号 | 漏洞 | 修复 |
|---|---|---|
| F-01 | 绕行能提价（需求不随距离下降，票价却挂实际里程） | 票价改用 `P_ref(OD 直线距离)`，绕行从「挣钱」变成「纯亏」 |
| F-02 | 经停航线每个 OD 都声称拥有整架飞机 | 段容量池按「航线 × 航段 × 舱位」共享 |
| F-03 | 中转产品 `route=None` 被跳过，绕过全部容量约束 | 每个产品携带 `legs`，统一进池按 yield 竞争 |
| F-04/05 | 同航线所有 OD 共用一个票价率，短途段无价格信号 | 每 OD 按自身距离取参考价，短途单位收益天然更高 |
| F-06 | 时刻占用对直飞高估一倍 | 改为 `2 × 触及航段数 × daily_flights` |
| F-08 | 航程约束与占机约束打架 | `validate_stopover()` 开线即校验 16h/8 段 |
| F-09 | AI 无法生成经停 | 受限枚举：给直飞航线加挂一个经停点，每端点最多评估 3 个 |

修掉 F-03 后，全网客流量从 216k 降到 187k、载客率不再超过 100%——
此前中转确实在出售不存在的座位。

## 仍未解决

1. **载客率 92.7% 偏高**。需求总量约为真实中国民航的 3 倍（纯能级制、无距离衰减，176 个 XL-L 城市对不论远近都给约 5,000 人/日）。
   已决策「维持纯能级制」，因此靠成本系数吸收，不调整需求模型。
2. **基准难度无破产**。需 `--cost-mult ≥ 1.2` 才出现淘汰。
3. 时刻 use-it-or-lose-it（R-513）未实现；二手飞机市场只有清算投放，没有交易。
4. **AI 锁死在 2 段经停**（`STOP["ai_max_segments"] = 2`）。3 段航线规则允许但只能由玩家创建，
   玩家侧入口尚未实现——这是 v1.0 的刻意取舍，不是遗漏（R-909）。
5. 机型更换、座位配置调整尚未实现。
