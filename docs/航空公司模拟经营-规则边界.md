## 1. 产品定位与核心循环

**一句话定位**：单机航空公司经营模拟。玩家与至多 50 家 AI 航空公司在同一真实航线网络里争夺客源，通过「选枢纽 → 开航线 → 排班定价 → 买/租飞机」扩张，在沙盒中长期经营。

**核心循环（唯一主线）**

```
选择/经营 HUB
  → 开通航线（点对点直飞，或 1–3 段经停航线）
  → 设定每日班次 + 起飞时刻 + 机型 + 三舱位票价与座位配置
  → 需求池按竞争分配客流
  → 日结算（收入/成本/载客率/口碑）
  → 月报表显示盈利与市值
  → 调整班次票价 / 扩张机队 / 开新航线 / 换 HUB
  → 循环
```

**边界判据**：任何规则若不能给上述循环增加一个「玩家决策点」或一个「可观测反馈」，Ver 1.0 不做。

| 类型 | 航段数 | 换机 | 经停次数 | 效用惩罚 | 生成来源 |

| 经停 Stopover | 2–3 | **否**（同一机尾全程） | 1–2 | `c_stop × stop_count` | 经停航线 |

## 3. 世界与机场数据规则

**机场字段（最低要求）**

| 字段 | 说明 | 用途 |
|---|---|---|
| IATA / 名称 / 城市 / 国家 / 区域 | 标识 | 显示与分组 |
| 经纬度 | 大圆距离 | 航程、油耗、时间 |
| 跑道等级 max_aircraft_class | 支线/窄体/宽体 | 限制机型 |
| 时刻容量 slot_capacity | 每日起降次数 | 班次上限 |
| 基础客流 base_traffic | 年旅客量（百万人次） | OD 需求计算 |
| 城市等级 city_tier | 1–4 级 | 商务客占比、票价承受力 |
| 起降费单价 | ¥M / 每次 | 成本 |
| 是否可作 HUB | 布尔 | 部分小机场不可作 HUB |

**规则约束**

- R-301 距离一律用大圆距离（km），航程判定含 5% 余量。
- R-302 任一机场每日起降总量 ≤ slot_capacity（含所有公司、含 AI）。
- R-303 时刻按 15 分钟为一格，每日 96 格。
- R-304 机场数据外置可配置，新增机场不改代码。

## 4. HUB 规则（Ver 1.0 重点）

### 4.1 数量与获取

| 项 | 规则 |
|---|---|
| HUB 上限 | 每家公司 ≤ 3 个（Ver 1.0） |
| 初始 HUB | 开局 1 个，由玩家在「可作 HUB」机场中选择 |
| 新增条件 | ① 该机场已有 ≥ 2 条玩家航线；② 该机场 `base_traffic` ≥ 10 百万人次/年；③ 该机场已停靠玩家在役飞机 ≥ 3 架；④ 支付一次性开设费（按机场规模 50–300 ¥M） |
| 年度维持费 | 每个 HUB 每年收取 `base_traffic × 8` ¥M 的设施与人员固定费，计入日结算 |
| 变更/关闭 | 冷却 12 游戏月；关闭退还 0，且 12 月内不得在原机场重开 |
| AI | 同一套规则；AI 按预期利润自动选 HUB |

> **防「假 HUB 圈地」**：仅「2 条航线」不足以换取 30% 时刻保留与 0.92 成本乘数——那会让人用两条 1 班/日 的亏损短途航线低成本套利。门槛必须包含**机场规模 + 实际机队投入 + 年度维持费**三项，使 HUB 成为真正的重资产承诺。

### 4.2 HUB 带来的收益（三条，全部要可计算）

1. **时刻优先权**：HUB 机场保留其容量的 30% 给该 HUB 公司优先申请，溢出后对外开放。**该保留额度同样受 §5 时刻回收规则（R-513）约束**，囤积不用即释放。
2. **本地市场偏好**：HUB 所在城市为起点的 OD 对，效用加成 `+hub_bonus`（建议 0.15）。
3. **规模成本效应**：以 HUB 为基地的飞机，维护与人员成本乘 `0.92`；HUB 机场的地面服务费乘 `0.9`。

> R-421 同一机场同一公司只能作为 1 个 HUB，不可重复计权。
> R-422 HUB 收益适用于「以该机场为端点」的航线；**中转产品在 HUB 换机时按 R-438 单独计 `hub_flag`，不受本条限制**。

### 4.3 中转行程（已确认：采用方案 A 轻量中转）

**已采纳方案 A**。对任一 OD 对，若玩家拥有 A→HUB 与 HUB→B 两条航线，且两段衔接等待 ≤ 4 小时，则生成一个「经 HUB 中转产品」作为额外的竞争候选，参与 logit 分配。

- 中转产品效用 = 两段加权平均票价 + 总旅行时间（含转机）+ 固定转机惩罚 `transfer_penalty`（建议 1.2）。
- 不做排班联动、不做行李/联程仿真、不做多枢纽多段（最多 1 次中转）。
- 同一 OD 对每个公司最多生成 1 个中转产品（取最优衔接）。
- 中转产品不占用额外时刻，但要求两段的班次时刻表在当日确实存在可行衔接。

**规则编号**

| 编号 | 规则 |
|---|---|
| R-431 | 中转产品仅作为需求分配层的候选，不产生独立的结算对象 |
| R-432 | 衔接等待上限 4h，下限 45min（含最短转机时间 MCT，按机场等级配置） |
| R-433 | 中转产品的可用座位 = min(前段剩余座位, 后段剩余座位) |
| R-434 | 同一 OD 对同一公司只取衔接时间最短的一条组合 |
| R-435 | AI 同样适用，AI 的 HUB 中转由同一算法自动生成 |
| R-436 | **中转必须换机**；不换机的两段组合归入「经停」类（§5.2），两类不可混算 |
| R-437 | 中转的前段/后段可以是经停航线的某一段，此时该段的剩余容量按 R-609 计算 |
| R-438 | **中转产品在 HUB 换机时 `hub_flag = 1`**，正常享受 `c_hub` 加成（修订 R-422 的字面含义：`c_hub` 的判据是「行程经过本公司 HUB 网络」，不是「HUB 是否为行程端点」） |
| R-439 | 经停点**不**触发 `hub_flag`（见 R-539 / R-543） |

> 已排除方案 B（无中转）：HUB 的策略深度不足，且无法体现多枢纽网络价值。

**经停 vs 中转 —— 一句话区分**

| | 经停 Stopover | 中转 Transfer |
|---|---|---|
| 换机 | 否，同一机尾 | 是 |
| 生成方式 | 玩家**直接设计**一条多段航线 | 系统**自动组合**两条已有航线 |
| 惩罚 | `c_stop = 0.35 / 次` | `c_trans = 1.2 / 次` |
| 依赖 HUB | 否 | 是（必须在 HUB 换机） |
| 时刻占用 | 每个航段各占 2 个机场的时刻 | 不额外占时刻（用的是既有航段） |

## 5. 航线结构、班次、时刻与经停

### 5.1 航线结构

| 编号 | 规则 |
|---|---|
| R-501 | 航线由 1–3 个航段构成：直飞（1 段）/ 经停（2–3 段，最多 2 个经停点） |
| R-502 | 每航线每日 1–14 班 |
| R-503 | 每班指定：机型、各航段起飞时刻、三舱位座位数、票价（定价见 §6.4） |
| R-504 | 玩家**航段数**软上限 **120 段**（含所有航线的全部航段）；超出部分每航段 +2% 固定成本 |
| R-505 | 机型必须满足：**每个航段**距离 ≤ 机型航程 × 1.05，且跑道等级允许 |
| R-506 | 同一架飞机同一时刻不得执行两个航段；排班校验必须拦截冲突并报错 |
| R-507 | 开通/关闭航线即时生效，当日已飞航班不受影响 |
| R-508 | 航线两端为 A 与 D；中间经停点 B、C 的航段**照常计入** R-504 的航段数（原「不额外计入航线数」的写法作废） |

### 5.2 经停航线（新增）

| 编号 | 规则 |
|---|---|
| R-531 | 一条航线最多 **3 个航段 / 2 个经停点**；服务的单向 OD 对数 = `n(n+1)/2`，n = 航段数 |
| R-532 | 经停点不得重复，且不得与航线两端同城（同城多机场视为同城，如 PEK/PKX） |
| R-533 | 全程同一机尾、同一航班号，经停**不换机**（换机即降级为中转产品，见 §4.3） |
| R-534 | **经停距离门槛**：`Σ 航段距离 ≥ 2,000 km` 才允许设置经停；低于此值只允许直飞 |
| R-535 | 单航段距离 ≥ 300 km |
| R-536 | **绕行系数**：`Σ 航段距离 / (A→D 大圆距离) ≤ 1.40`，禁止为凑经停而绕远 |
| R-537 | **防拼远程**：`总航程 ≤ 机型航程 × 1.30`（允许有限延伸，禁止 3 段拼出远程航线） |
| R-538 | 经停点机场的跑道等级须满足该机型 |
| R-539 | 经停身份本身**不产生** HUB 收益；若经停点恰好是本公司 HUB，则按 §4.2 照常计 |
| R-540 | 一架飞机每日执飞航段数按 R-510 累计，经停航线不豁免 |
| R-541 | 经停地面时间计入占机时间：支线 30 / 窄体 45 / 宽体 90 min，另加 15 min 上下客附加 |
| R-542 | **不设「经停经过 HUB」的惩罚**：经停点无论是否为 HUB，均不加额外效用惩罚、不收额外时刻或费用 |
| R-543 | 经停点若为本公司 HUB，仅按 R-539 处理（不产生 HUB 收益），不叠加任何负向项 |

> **为什么明确不设经停-HUB 惩罚（决策记录 D-37）**
>
> 1. 经停与等量直飞在**航段消耗、时刻消耗、机组工时上完全等价**（见下方推演），经停没有物理上的效率优势，因此不存在「经停挤占 HUB」的运营理由。
> 2. 经停的真实优势只有「航线计数」与「固定成本」两项，已在 R-504 与 §8.1 改按航段计费后消除。
> 3. 若给 HUB 经停加惩罚，玩家会把经停点搬到**非 HUB 的中小机场**（那里时刻最便宜），结果是经停总量不减、HUB 相对地位反而下降——想保护 HUB 却把流量赶离 HUB。
> 4. R-539 已使经停点失去 HUB 收益，再加惩罚即为双重负向，UI 无法解释。

**为什么经停与直飞等价（推演）**

```
经停方案：A→B→C，1 个每日往返
  物理执行 6 个航段；服务 A-B / B-C / A-C 各 2 个方向 = 6 个 OD 班次
  时刻占用 12 个事件

直飞方案：A-B、B-C、A-C 各 1 个每日往返
  物理执行 6 个航段；服务同样 6 个 OD 班次
  时刻占用 12 个事件
```

两者完全等价。经停唯一的收益是「1 条航线覆盖 6 个 OD」，这纯粹是**计数学与成本分摊**层面的套利，与 HUB 无关。

**门槛为什么是 2,000 km**

短航线上做经停，只会白占两端机场的时刻，却把 OD 覆盖从 1 个变成 3 个——这是纯粹的「刷覆盖」。2000 km 约合 2.5 小时飞行，在这个距离上经停才有现实意义（如 乌鲁木齐—兰州—成都，约 2,300 km）。该阈值外置可配。

**示例：3 段航线服务的 OD 对**

```
航线 A → B → C → D          2 个经停点，3 个航段
单向服务 OD：A-B / B-C / C-D / A-C / B-D / A-D      共 6 个
一架飞机一个往返 = 6 个航段 → 直接触及 R-510「每日 ≤ 8 段」
```

这就是经停的收益与代价：覆盖 6 个 OD，但 1 架机一天只够 1 个完整往返。

### 5.3 机队周转

| 编号 | 规则 |
|---|---|
| R-509 | 每架飞机每日**占机时间** ≤ 16 小时 |
| R-510 | 每架飞机每日**执行航段数** ≤ 8 段 |
| R-511 | 跨日航班（如 23:30 起飞、次日 01:00 落地）的占机时间全部计入**起飞日**，不得借跨日规避 R-509/R-510 |
| R-512 | 航线班次超过机队可支撑能力时，排班校验直接报错，不允许提交 |

```
单航段占机时间 = 飞行时间 + 过站时间
飞行时间       = 距离 / 巡航速度
过站时间       = 支线 30min / 窄体 45min / 宽体 90min
                                                （飞往非 HUB 机场时 ×1.15）
经停地面时间   = 同型过站时间 + 15min（见 R-541）
每日占机总时长 = Σ 该飞机当日执行的所有航段占机时间（含经停地面时间）
```

> 这一条是**整个经济模型的锚**。若缺少每日占机上限，1 架窄体机可在一条 500km 航线上排 14 班/日（现实仅 6–8 段），座位供给将凭空膨胀约一倍，导致 logit 分母中所有公司份额被摊薄、全局票价与利润率集体崩塌。**禁止在实现阶段以「方便玩家」为由放宽此约束。**

### 5.4 时刻与回收

| 编号 | 规则 |
|---|---|
| R-513 | 时刻回收：机场任一时刻格在连续 60 游戏日内的实际使用率 < 80%，该时刻收回公共池 |
| R-514 | 时刻回收同样适用于 HUB 保留的 30% 额度，不设例外 |
| R-515 | 时刻一经收回，原公司重新申请时排在其他申请者之后 |
| R-516 | **经停航线的每个航段，在起降两个机场各占 1 个时刻格**；经停点的到达与起飞分别占用 |
| R-517 | 班次增加需两端机场（及所有经停点）均有剩余时刻；任一点不足则整班不可提交 |

- 使用率 = 该时刻格在 60 日滑窗内实际执飞班次 / 已获批班次。
- 每日结算时滚动校验；触发回收需在 UI 给出提前 30 日的警告。
- 目的：防止大机场（PEK/LHR 等）被「1 班/日的亏损短途航线」占满，造成后期新进入者与玩家自身都无法扩张的死局。

### 5.5 时刻便利度 freq_score

```
freq_score = w1 * ln(1 + daily_flights) + w2 * peak_coverage
peak_coverage = (落在高峰的班次数) / daily_flights      # 0..1
建议 w1 = 1.0, w2 = 0.6
```

> 经停航线的 `freq_score` 按**每个 OD 对**单独计算：某 OD 的班次数 = 承载该 OD 的行程产品数（同一航线的一次经停往返对该 OD 只算 1 班）。

## 6. 需求与竞争分配规则（核心，最高优先级冻结）

### 6.1 需求池生成（能级制）

> v0.6 起废弃重力模型，改为能级制。原因：重力模型的 `alpha / beta / d_max` 三个形状参数在现有数据上共线不可识别（详见 `calibration/report.md` §2），且把机场吞吐量直接当成 O&D 需求会系统性高估枢纽。能级制同时解决这两个问题。

**第一步：机场能级**

| 能级 | 名称 | 年吞吐量阈值 | 需求权重 `w` |
|---|---|---|---|
| XL | 超大机场 | ≥ 80 百万人次 | 1.0000 |
| L | 大型机场 | 45 – 80 | 0.4624 |
| M | 中型机场 | 25 – 45 | 0.2138 |
| S | 小型机场 | 10 – 25 | 0.0989 |
| R | 支线机场 | < 10 | 0.0457 |

- 城市能级取其**全部机场吞吐量之和**所对应的档位（如上海 = 虹桥 45.6 + 浦东 76.2 = 121.8 → XL）。
- 权重构成等比阶梯：**每降一档乘 0.4624**。这一比率由 XL→L 的锚点直接解出，并用 S 档锚点交叉验证（偏差 −11%）。

**第二步：总出行需求**

```
D_total(A,B) = C · w(scale_A) · w(scale_B) · C_region · conn_A · conn_B
C            = 21,455
```

> 注意：`D_total` 是**总出行需求（含高铁、自驾）**，不是航空客流。距离**不进入**这个公式。

**第三步：方式分担（航空 vs 其他交通）**

```
D_air(A,B) = D_total(A,B) · sigmoid(c0(d))
c0(d)      = c0_short + (c0_long − c0_short) · clamp((d − 600) / 1800, 0, 1)
c0_short   = −1.119      c0_long = 2.442
```

| 航距 km | 航空分担率 |
|---|---|
| 400 | 24.6% |
| 800 | 32.7% |
| 1,200 | 51.7% |
| 1,800 | 77.8% |
| ≥ 2,400 | 92.0% |

这是距离**唯一影响需求量**的地方，且它的含义是「高铁替代」，不是「距离让人不想出门」。

**第四步：枢纽连通度（D3 决策）**

```
conn(i) = min(1.80, 1 + 0.50 · ln(1 + routes_i / 100))
routes_i = 该机场全部在营航段数（所有公司，含经停段）
```

| 在营航段数 | 0 | 50 | 100 | 200 | 400+ |
|---|---|---|---|---|---|
| `conn` | 1.000 | 1.203 | 1.347 | 1.549 | 1.800 |

- 这是**全模型唯一随时间变化的需求项**：首尔、迪拜这类中转城市开局按能级拿基础 OD，随着航段铺设而吸引力上升。
- 乘子同时作用于航线两端，因此「把对手的枢纽做大」也会抬高你自己的 OD 池。

**区域系数**（`C_region`，以国内 1.0 为基准）

| 区域对 | 系数 | 置信度 |
|---|---|---|
| CN–CN | 1.000 | — |
| CN–GCR（港澳台） | 0.536 | 中 |
| CN–ASIA | 0.181 | 中 |
| CN–AMR | 0.085 | 中 |
| CN–EUR | 0.059 | 中 |
| CN–OCE | 0.146 | 低（单锚点） |
| CN–MEA | 0.047 | **极低（无锚点，占位）** |

> 校准结果：对数域 R² = 0.869，平均绝对误差 23.7%，京沪 −9.3%。完整残差表见 `calibration/report.md`。

### 6.2 舱位分层

```
D_air,economy  = D_air * (1 - b - f)
D_air,business = D_air * b
D_air,first    = D_air * f

b = clamp(0.04 + 0.010 * (tier_A + tier_B) + 0.00004 * d, 0.04, 0.30)
f = 0.0            # 头等仅在 tier_A + tier_B ≥ 7 且 d ≥ 4000 时开放，占比 ≤ 0.04
```

### 6.3 竞争分配（分舱位嵌套 logit）

对 OD 对、舱位 c，参与者 = 玩家 + 所有提供该 OD 该舱位座位的 AI + 「不飞」外部选项。**候选单位是行程产品**（直飞 / 经停 / 中转），不是航线。

```
U_i = -c_price * ln(P_i / P_ref)          # 价格项，P 为该舱位人均票价
      + c_time  * (-T_i / 10)             # 总旅行时间（含经停地面、换机等待）
      + c_freq  * freq_score_i
      + c_rep(d) * (rep_i - 50) / 50       # 距离相关，见下
      + c_hub   * hub_flag_i              # 从/到本公司 HUB
      - c_stop  * stop_count_i            # 经停惩罚（每经停 1 次）
      - c_trans * transfer_count_i        # 换机惩罚（中转 1 次）

share_i = exp(U_i) / (exp(U_0) + Σ_j exp(U_j)),   U_0 = 0
demand_i = D_air,c * share_i
```

**已标定系数**

| 系数 | 取值 | 来源 |
|---|---|---|
| `c_price` | **2.182** | 由弹性目标反解（s=0.45 时 ε=−1.20） |
| `c_stop` | **0.335** | 由中转反超门槛反解（经停 2 班/日 ≡ 中转 10 班/日） |
| `c_trans` | 1.20 | 设计值 |
| `c_freq` | 0.55 | 设计值 |
| `c_hub` | 0.15 | 设计值 |
| `c_time` | 0.25 | 设计值，**未校准** |
| `c_rep(d)` | 见下 | **未校准**，设计值 |

**`c_rep` 随距离变化（D2 决策：距离从需求侧转入口碑侧）**

```
c_rep(d) = min(1.20, 0.25 + 0.000075 · d)
```

| 航距 km | 300 | 1,000 | 2,000 | 4,000 | 8,000 | 10,400 |
|---|---|---|---|---|---|---|
| `c_rep` | 0.273 | 0.325 | 0.400 | 0.550 | 0.850 | 1.030 |

> **这是「自动引导使用更舒适机型」的机制。** 长航线上口碑的边际权重被放大到短途的 3–4 倍，而口碑中的 `comfort_score` 由机型舒适度驱动。因此用舒适度低的机型执飞长航线会直接损失份额——不需要额外写「机型航程限制」这类硬规则，市场会自己淘汰不适配的机型。

**`c_stop` 的推导（已解决 v0.5 的疑虑）**

v0.5 曾担心「经停的固定成本套利被消除后，`c_stop = 0.35` 会让经停无人使用」，因而建议下调到 0.20–0.25。**这个担心是错的**：`c_stop` 只作用于需求侧份额，与成本侧无关。消除成本套利不改变任何份额计算，因此 `c_stop` 无需下调。反解结果 0.335 与 0.35 几乎一致。

```
门槛条件：c_freq × [ln(1+10) − ln(1+2)] + c_hub = c_trans − c_stop
0.55 × 1.2993 + 0.15 = 0.864  →  c_stop = 1.20 − 0.864 = 0.335
```

> 三类产品的效用差由惩罚项承担：直飞 0、经停 `0.35/次`、换机中转 `1.2/次`。这样「经停」永远劣于同 OD 直飞、但优于换机中转，符合旅客偏好次序。

**约束**

- R-601 玩家获得客流 ≤ 其该 OD 该舱位座位供给；超出部分流失，不溢出到其他公司。
- R-602 座位供给为 0 的公司不进入分母。
- R-603 只对「至少有一家运营」的 OD 对做分配计算（性能边界，见 §12）。
- R-604 价格项用「人均票价 / 该 OD 该舱位参考价」，参考价为距离与舱位的函数，保证跨 OD 可比。
- R-605 所有候选产品的效用必须在同一量纲下，价格一律折算为「每 1000 km 含税票价」。
- R-606 **座位门槛**：某公司在某 OD 某舱位的单日座位供给 < 30 座时，不进入 logit 分母，直接视为未进入该市场。
- R-607 座位门槛的目的是阻断「份额抑制术」：用小座位产品稀释分母、压低对手份额，自己再按 R-601 流失需求。
- R-608 **候选产品上限**：每 OD 每公司最多 3 个候选产品（1 直飞 + 1 经停 + 1 中转）；超标时只保留效用最高者。
- R-609 **段容量约束**：某航段承载的全部 OD 客流之和（含跨越该段继续乘坐的旅客）≤ 该航段座位数。
- R-610 段容量不足时的分配顺序：按 `yield = OD 票价 / 该 OD 占用航段数` 降序分配，被截断的旅客视为流失（收入不计）。
- R-611 行程产品可用座位 = `min(各航段剩余容量)`。

> R-609/R-610 是经停机制的关键：全程 A→D 的旅客要占用 A-B、B-C、C-D 三段的座位，所以「多拉长途」会挤掉短途客。这正是现实中 leg-based 收益管理的核心，也让经停不是无脑最优。

### 6.4 票价与收益

```
收入 = Σ_OD Σ_c demand_i,c * price_i,c
```

**定价粒度（修订 D-14，因经停引入多 OD）**

| 编号 | 规则 |
|---|---|
| R-631 | 玩家为每条航线设定**价格指数**（相对参考票价的倍数，默认 1.0，区间 0.50–1.50）；若改为手工填写 OD 票价，按下条计算后乘指数 |
| R-632 | 各 OD 票价 = `P_ref(OD 两端直线距离, 舱位) × 价格指数`。**必须用直线距离，不能用实际航段里程**——否则绕行会直接提价（见附录 F-01） |
| R-633 | 允许玩家对单条航线的**单个 OD 覆盖票价**（高级选项，默认关闭），覆盖后不受 R-632 约束 |
| R-634 | 票价不得低于 `0.6 × 该 OD 的边际成本参考价`（统一按 OD 距离与行业平均油耗计算，不用玩家机型） |
| R-635 | 不做班次级差别定价（同航线同 OD 同舱位同价） |

> **为什么改掉「航线级票价率」**：v0.1 用「票价率 × 实际航段里程」，两个后果都是错的。
> 一是绕行能提价（F-01）；二是同航线所有 OD 共用同一个单位里程票价，本地短途客的单位收益溢价被抹平，
> 段容量截断因此没有价格信号可依（F-04/F-05）。
> 改成 `P_ref(直线距离)` 后，参考价曲线自带 `b ≈ 0.8` 的短途溢价，每条 OD 的单位收益天然不同，
> 短途段在座位竞争中会自动占优——这正是现实中经停航线能靠本地客填满中间段的原因。

### 6.5 品质因子（已冻结：完全被动机制）

因 D-07 排除了营销投放与常旅客，口碑改为完全被动生成：

```
# 每条航线各自计算，再做客流加权
comfort_w = 10 + 20 · clamp((航距 − 1500) / 5000, 0, 1)     # 舒适度权重随航距上升
rep_route_target = 50
    + 25 * on_time_rate_score(route)
    + 10 * fleet_age_score(route)
    + comfort_w * comfort_score(route)                        # 短途 10 分，远程最高 30 分
    +  5 * hub_coverage_score
    - 15 * cancel_rate(route)                    # 取消率惩罚（0..1）
rep_route = clamp(rep_route + (rep_route_target - rep_route) * 0.05, 0, 100)
rep = Σ(rep_route × flow_route) / Σ flow_route   # 客流加权，见 R-617
on_time_rate_score = clamp((on_time_rate - 0.70) / 0.30, 0, 1)
fleet_age_score    = clamp(1 - avg_age / 25, 0, 1)
```

> **为什么 `comfort_w` 要随航距放大（实现期修订）**：按原式固定 10 分权重，机型舒适度只影响约 3 个口碑点，
> 折算进 logit 的效用差约 0.05，几乎不可见——「长航线自然淘汰不舒适机型」这条核心设计等于空转。
> 改成随航距从 10 升到 30 分后，低舒适度机型执飞 6,000 km 以上航线的口碑损失约 11 点，
> 对应份额差约 20%，机制才真正成立。

> 口径注意：`hub_coverage_score` 是公司级指标，其余是航线级指标。混合使用会导致「HUB 多则每条航线口碑都高」，这符合直觉，保留。

- R-616 `rep` 必须 clamp 到 0–100；`penalties` 只保留「取消率」一项（超售机制在 Ver 1.0 不存在，故删除超售投诉项）。
- R-617 **口碑按客流加权**：`rep = Σ(航线口碑 × 航线客流) / Σ(航线客流)`，准点率与取消率均按航线统计后加权。这取代了 v0.3 的「全网统一」口径（关闭 E-06）：高客流航线上用旧机代价大，低客流航线上影响小——这本身就是正确的经济激励，不需要额外机制。
- R-618 新开航线的口碑初始值 = 公司当前全网口碑，不从固定 50 起步，避免新航线带来的口碑跳变。
- 口碑变化惯性 5%/日；玩家影响口碑的唯一手段是运营质量与机型选择，**无任何主动投放**（D-12）。
- 由此产生的设计后果：需求侧的玩家杠杆收敛为「航段结构 / 班次 / 时刻 / 机型 / 票价 / HUB 布局」六项，UI 与教程必须围绕这六项组织。

### 6.6 航班取消规则

| 编号 | 规则 |
|---|---|
| R-621 | 取消原因仅两类：机龄可靠性导致的随机取消、玩家主动取消 |
| R-622 | 取消航班的旅客全额退款（收入不计），并支付补偿金 `订单票价 × 0.5` |
| R-623 | 取消率计入航线级口碑惩罚项（R-616 中的 `cancel_rate`），再按 R-617 加权 |
| R-624 | 玩家主动取消当日已排班次的，额外扣一次「运营混乱费」（每班 5 ¥M） |
| R-625 | 随机取消概率 = `0.5% + 0.3% × (机龄 > 12 ? 机龄 - 12 : 0)`，每日每班独立判定 |
| R-626 | **经停航线的取消粒度是「整条航线的整班」**：某一段故障即整班取消，不允许只取消其中一段 |

> 目的：取消不能是免费逃生通道。R-622 使「取消」在财务上劣于「降价卖票」，R-624 阻断「每班随时取消再重排」的刷法。

## 7. 机队、二手市场与租赁

### 7.1 机型参数（约 45 种）

| 参数 | 说明 |
|---|---|
| 类别 | 支线 / 窄体 / 宽体 / 远程 |
| 座位数 | 三舱位最大座位配置 |
| 航程 | km，实际可用 = 航程 × 0.95 |
| 巡航速度 | km/h，决定旅行时间 |
| 油耗 | 每座每百公里油耗（kg） |
| MTOW | 最大起飞重量，影响起降费与导航费 |
| 跑道需求 | 对应机场跑道等级 |
| 目录价 / 月租金 | ¥M |
| 维护费率 | ¥M / 飞行小时（新机基准） |
| 交付周期 | 新机下单到交付的游戏日 |

### 7.2 新机 / 二手 / 租赁

| 方式 | 规则 |
|---|---|
| 新机采购 | 全款付清或 30% 首付 + 贷款；交付周期 60–180 游戏日，期间占压资金 |
| 二手市场 | 机龄 0–25 年；价格 = 目录价 × 折旧曲线 × 状态系数；供给随机刷新（每月） |
| 折旧曲线 | `v(age) = max(0.10, 1 - 0.065*age - 0.0015*age^2)` |
| 状态系数 | 0.85–1.15，随机；影响维护费率与可靠性 |
| 湿租/干租 | 月租 = 目录价 × 0.55%；押金 = 3 个月租金；提前退租罚 2 个月租金 |
| 出售 | 按当前折旧价 × 0.85 立即成交，或挂市场 30 天按市价 |
| 机龄影响 | 维护费率 × (1 + 0.04 × age)；可靠性下降 → 延误与取消概率上升，进而拖累口碑 |

### 7.3 约束

- R-701 每架飞机有唯一 ID 与状态（待交付/在役/维修/已售）。
- R-702 在役飞机若当日无排班，仅额外扣「停机与人员费」（15 ¥M/架/日）。**折旧与租金已含在日结算中，不得重复计入闲置成本。**
- R-703 飞机数量上限 200 架。
- R-704 三舱位座位配置之和 ≤ 机型最大座位数。
- R-705 机队残值统一口径：**一律取「当前二手市场价」**（`目录价 × v(age) × 状态系数`），不使用直线折旧账面净值。
- R-706 航程判定分两级：**单段**距离 ≤ 航程 × 1.05（R-505）；**整条航线总航程** ≤ 航程 × 1.30（R-537）。两者必须同时满足。
- R-707 `capacity_mix` 字段：机型的「经济/商务/头等默认座位比」，供经停航线一键配置三舱座位时作为初始值。
- R-708 二手市场刷新与 AI 破产清算的飞机投放共用同一市场队列，先到先得。

## 8. 财务与结算

### 8.1 日结算（每个游戏日一次）

```
收入  = 客运收入 − 取消退款 + 其他（Ver1.0 无）
成本  = 燃油 + 起降费 + 导航费 + 地面服务 + 维护 + 折旧 + 租金 + 人员 + HUB 固定 + 贷款利息 + 取消补偿
燃油    = Σ 航班 (油耗/座/百km × 距离/100 × 座位数) × 油价
起降费  = Σ 航班 机场起降单价 × (MTOW / 70t)
导航费  = Σ 航班 距离 × MTOW系数 × 单价
维护    = Σ 飞机 飞行小时 × 维护费率 × 机龄系数
折旧    = 直线 20 年，残值 10%（自有）；租赁飞机不折旧，计租金
人员    = 固定基数 + 每架在役飞机系数 + 每航段系数 × Σ航段数
          # 关键：按「航段数」而非「航线条数」计，堵住经停的固定成本套利（D-34）
HUB固定 = Σ HUB 机场 (年度维持费 / 360)
利息    = 贷款余额 × 年利率 / 360        # 与 1 年 = 360 日口径一致
取消补偿 = Σ 取消航班 旅客数 × 票价 × 0.5（见 R-622）
```

> 口径说明：**折旧**是成本侧会计项（直线法）；**机队残值**用于市值与贷款额度，一律取二手市场价（R-705）。两者口径不同是刻意的，不可混用。

### 8.2 月报表

- 损益表（收入/成本分项/EBITDA/净利）
- 资产负债表（现金、机队残值、负债、权益）
- 运营 KPI（载客率、准点率、航线数、机队规模、市场份额）

### 8.3 融资与破产

| 项 | 规则 |
|---|---|
| 贷款额度 | `min(机队残值 × 0.6 + 过去 12 月 EBITDA × 3, 权益 × 2.0)` |
| **杠杆上限** | `负债 / 权益 ≤ 2.0`（硬上限，超出则拒绝新增贷款） |
| 年利率 | 基准 6%，按负债率在 6%–12% 间上浮 |
| 破产判定 | 现金 < 0 且无法新增贷款 → 玩家立即失败；AI 退出市场并清算（航线与时刻释放） |
| 市值 | `EBITDA_年化 × m + 机队残值 + 现金 − 负债`，`m = clamp(8 − 4 × 净负债率, 4, 8)`，`净负债率 = 负债 / (负债 + 权益)` |

> **防杠杆正循环**：原公式「贷款额度 = 机队残值 × 0.6 + EBITDA × 3」会使「借钱买机 → 残值↑ → 额度↑」形成自我强化循环。加入 `权益 × 2.0` 上限后，扩张速度被权益约束锁住。
>
> **防市值刷分**：原市值公式对 EBITDA 统一乘 8，高杠杆公司会被系统性高估（利息已从 EBITDA 扣出，但负债本金未反映在倍数上）。改为按净负债率下调倍数后，「借钱冲市值」不再优于「用利润扩规模」。

### 8.4 时间刻度

| 项 | 值 |
|---|---|
| 1 游戏日 | 60 秒真实时间（1× 速度） |
| 倍速 | 0（暂停）/ 1× / 4× / 16× |
| 1 游戏月 | 30 日 |
| 1 游戏年 | 360 日 |
| 日结算预算 | < 100 ms |
| 起始资金（三档难度） | 2,000 / 5,000 / 12,000 ¥M |

| 参数 | 轻松 | 标准 | 硬核 |
|---|---|---|---|

## 9. AI 竞争对手规则

| 编号 | 规则 |
|---|---|
| R-901 | AI 数量 1–50 可配置，开局随机分配 HUB 与起始机队，规模分小/中/大三档 |
| R-902 | AI 与玩家共用同一套规则、同一份参数表，不允许特权 |
| R-903 | AI 决策频率：每 7 游戏日一次（扩张/关停），票价每 30 日微调 |
| R-904 | AI 决策只使用启发式评估，不做全局最优搜索（性能约束） |
| R-905 | AI 性格参数 3 维：扩张激进程度、价格策略、对亏损容忍度 |
| R-906 | AI 破产后释放航线与时刻，不复活 |
| R-907 | AI 不得读取玩家未公开信息（决策基于公开可观测状态） |
| R-908 | **AI 经停候选生成受限**：只从「已有航线端点的邻近机场」扩展，单次最多评估 3 个扩展点 |
| R-909 | **v1.0 决策：AI 只生成 2 段（1 个经停点）航线，不生成 3 段**。理由：3 段候选组合从 3 个/端点膨胀到 9 个/端点，且 R-537 允许 A320 拼出 8,190 km 航线，经济上可疑。3 段保留给玩家，AI 侧由 `STOP.ai_max_segments = 2` 硬约束 |
| R-910 | AI 破产清算时，其机队按 **70% 二手市价**立即投放二手市场（关闭 E-20），航线与时刻回公共池 |
| R-911 | AI 与玩家对同一 OD 的候选产品上限一致（R-608），AI 不得生成超过 3 个 |
| R-912 | **AI 定价以利润为目标，不以载客率为目标**：在「降价填满」与「涨价降载客」之间比较 `(票价 − 单位变动成本) × 客流`，取更优者 |
| R-913 | **允许航班售罄**。当提价后仍能卖满时，提价总是更优；不必把载客率压到某个固定目标值 |
| R-914 | AI 票价区间为 `[0.50, 1.50] × 参考价`，且每次调整最多移动目标值的 60%（防振荡） |

**AI 决策优先级（每 7 日）**

1. 亏损航线（连续 2 个月载客率 < 45%）→ 关停
2. 现金充裕且有可用飞机 → 评估 Top-N 未开通 OD 的预期利润，开通最优
3. 现有航线加挂经停点（在 R-534 门槛内）→ 评估增量 OD 收益
4. 机队不足且航线需求旺盛 → 采购/租赁
5. 票价偏离目标载客率 → 调整 ±10%

## 附录 F 经停（STOP）已知问题清单

> 状态：**F-01 / F-02 / F-03 / F-04 / F-05 / F-06 / F-08 / F-09 已修复**；F-07 已因 F-01 的修复而失去危害；F-10 明确不做。

**已修复项（模拟内核已实现）**

| 编号 | 修复方式 |
|---|---|
| F-01 | 票价改用 `P_ref(OD 两端直线距离)`（R-632）。绕行不再提价，反而只增加油耗与时间——从「挣钱」变成「纯亏」 |
| F-02 | 段容量池改为按「航线 × 航段 × 舱位」建立，一条航线的所有 OD 共享同一池，座位不再重复出售 |
| F-03 | 每个行程产品携带 `legs`（实际占用的航段列表），中转产品与直达产品进同一池按 yield 竞争，不再绕过约束 |
| F-04 / F-05 | 改为每 OD 按自身距离取参考价，短途 OD 的单位里程票价天然更高，段容量按 yield 排序时短途段自动占优 |
| F-06 | 时刻占用改为 `2 × 该机场被触及的航段数 × daily_flights`（原来一律 ×4，直飞高估一倍） |
| F-07 | 因 F-01 修复而失效：绕行不再带来票价收益，「2000 km 只是下限」不再构成套利空间 |
| F-08 | `validate_stopover()` 在开线时即校验往返占机 ≤ 16h 与航段数 ≤ 8 段，不再出现「开得出但飞不了」 |
| F-09 | AI 用「给直飞航线加挂一个经停点」的受限枚举（每个候选端点最多评估 3 个扩展点），不做 3 段组合搜索 |
| — | 顺带修正：多段航线的载客率改按「航段」统计，避免 >100% |

| 编号 | 问题 | 等级 | 说明 |
|---|---|---|---|
| F-01 | **绕行能提价，且需求不随距离下降** | **P0** | 票价按 `实际航段里程` 计算（R-632），而需求由能级决定、与距离无关（D-38）。于是把经停点绕远 40%（R-536 允许的上限）→ 票价直接涨 40%，需求几乎不掉（时间惩罚仅 `0.25/10h ≈ 0.025/小时`）。**绕行变成纯增收手段**，R-536 反而成了「允许你多收 40%」的许可证。 |
| F-02 | **经停航线座位被重复出售** | **P0** | `build_products` 为 n 段航线的每个 OD 生成产品，每个产品的座位都写成「整架飞机」（`daily_flights × 机型座位 × 舱位比`）。一条 3 段航线生成 6 个产品，各自声称有同样的座位数，总供给是物理座位的数倍。段容量截断在 logit **之后**才修正，但份额已经按虚高座位算完了。 |
| F-03 | **中转产品完全绕过段容量约束** | **P0** | `allocate` 的段容量循环只处理 `route is not None` 的产品。中转产品的 `route` 是 `None`，被直接跳过；而它的座位 = `min(两段座位)`，这两段的座位**同时已经卖给了各自的直达 OD**。同一批座位卖两次。（这也是早期出现「载客率 100.5%」的原因。） |
| F-04 | **段容量截断对短途段没有保护** | P1 | R-610 按 `票价 / 占用段数` 降序分配。但同一航线的所有 OD 共用一个票价率（R-631），所以 A-B 与 A-C 的「每段收益」几乎相等，短途段拿不到优先权。现实中经停航线正是靠本地短途客填满中间段；这里是先到先得的等值竞争，结果随机。 |
| F-05 | **同航线所有 OD 共用一个票价率** | P1 | 一条 3 段航线服务 6 个 OD，全部按 `票价率 × OD 里程` 出价。现实中本地短途客单位里程票价显著更高，这里被抹平了。后果是 F-04，以及「长途 OD 天然吃掉全部座位」。 |
| F-06 | **时刻占用对直飞高估一倍** | P2 | `slots_used[code] += 4 × daily_flights` 对每个航段机场都加 4。直飞航线每个机场每天实际只有 2 次起降事件（往返各一次），应为 2。经停航线的中间机场确实是 4（两个方向各到达+起飞），所以这段代码**对直飞错、对经停对**，接入经停后口径会不一致。 |
| F-07 | **R-534 的 2000 km 门槛只是下限** | P2 | 只限制「总航程 ≥ 2000 km 才允许经停」，没有上限。配合 1.4 的绕行系数，一条 2500 km 的直线城市对可以做出 3500 km 的经停航线。 |
| F-08 | **航程约束与占机约束会打架** | P2 | R-537 只查总航程 ≤ 航程 × 1.30，但 3 段各 2,700 km 的 A320 航线一天跑完往返就超过 16 h，会被 R-509 拦截。两条规则的方向相反，校验时机也不同（一个在开线时、一个在排班时），玩家会看到「航线开得出但飞不了」。 |
| F-09 | **AI 无法生成经停航线** | P1 | 3 段组合的候选空间是 59×58×57 ≈ 19 万，必须限制。已按「给直飞航线加挂一个经停点、每端点最多 3 个候选」实现，且 AI 锁死在 2 段（R-909）。 |
| F-10 | **无法区分技术经停与商业经停** | P3 | 每个经停点必然生成 OD 产品，无法表达「只加油不上下客」。现实中大量经停是纯技术性的。 |

**接入经停前的最小修补顺序建议**

```
1. 先修 F-03（中转绕过段容量）——它与经停无关，但会让经停的容量核算彻底失真
2. 再修 F-02（产品座位按「段」而非「机」计），与 F-03 一起做，同一处代码
3. 修 F-01：票价改用「两端大圆距离」而非实际航段里程，或给绕行加显式惩罚
4. 修 F-05/F-04：票价率按 OD 距离分段（短途溢价），截断才有价格信号
5. 最后才接入 AI 生成（F-09）与时刻口径（F-06）
```
