## 1. 产品概述

### 1.1 定位

单机航空公司经营模拟。玩家与至多 50 家 AI 在同一张真实航线网络上争夺客源，通过
「选枢纽 → 开航线 → 排班定价 → 买/租飞机」扩张，在沙盒中长期经营。

### 1.2 核心循环

```
选择/经营 HUB
  → 开通航线（直飞 或 1 个经停点）
  → 设定每日班次、机型、三舱位座位配置、价格指数
  → 需求池按竞争分配客流
  → 日结算（收入 / 9 项成本 / 载客率 / 口碑）
  → 月报表显示盈利与市值
  → 调整班次与价格 / 扩张机队 / 开新航线 / 换 HUB
  → 循环
```

**边界判据**：任何功能若不能给上述循环增加一个「玩家决策点」或一个「可观测反馈」，Ver 1.0 不做。

### 1.3 目标用户与平台

- 桌面浏览器（Chrome / Edge），单机运行，无服务端依赖
- 简体中文界面，货币单位 **¥M（百万元人民币）**
- 一局典型时长 10–60 小时（按 1× 速度，1 游戏日 = 60 秒）

### 1.4 时间尺度

| 项 | 值 |
|---|---|
| 1 游戏日 | 60 秒真实时间（1×） |
| 倍速 | 0（暂停）/ 1× / 4× / 16× |
| 1 游戏月 | 30 日 |
| 1 游戏年 | 360 日 |

| 时刻 Slot | 机场一次起降许可 |

| 口碑 rep | 0–100 的服务质量评分，按航线计算、按客流加权 |
| 价格指数 | 相对参考票价的倍数，0.50–1.50 |
| 市值 | `EBITDA年化 × m + 机队残值 + 现金 − 负债`，`m` 随净负债率下调 |

## 3. 功能需求

> 优先级：**P0** = 缺了游戏不成立；**P1** = Ver 1.0 必须交付；**P2** = 可延后。
> 每条需求给出「验收」标准，验收必须是可观测或可计算的结果。

### 3.1 世界与数据（FR-1xx）

**FR-101 机场库加载（P0）**
系统从外置数据文件加载机场库，至少包含 IATA 码、城市、国家、区域、经纬度、年吞吐量、
中转占比、跑道等级、城市等级。
*验收*：加载 300 个机场不修改任何代码；缺失字段时启动报错并指出字段名。

**FR-102 机场能级划分（P0）**
按机场年吞吐量自动分档：XL ≥ 80、L ≥ 45、M ≥ 25、S ≥ 10、R < 10（百万人次/年）。
*验收*：给定吞吐量 79.9 / 80.0，前者为 L、后者为 XL；边界值有单元测试。

**FR-103 城市聚合（P0）**
城市客流 = 该城市全部机场吞吐量之和；城市能级由该和值决定；城市坐标按吞吐量加权。
*验收*：上海（虹桥 45.6 + 浦东 76.2 = 121.8）能级为 XL；删除任一机场后能级按新和值重算。

**FR-104 区域系数（P0）**
跨区域 OD 的规模乘子：CN–CN 1.000、GCR 0.536、ASIA 0.181、AMR 0.085、EUR 0.059、
OCE 0.146、MEA 0.047（占位）。
*验收*：北京–上海乘子为 1.0；北京–法兰克福乘子为 0.059。

**FR-105 机型库（P0）**
机型数据外置，包含类别、座位数、航程、巡航速度、每座百公里油耗、最大起飞重量、
舒适度、目录价、维护费率。
*验收*：新增机型只需改数据文件；Ver 1.0 至少 10 种，覆盖支线/窄体/宽体。

**FR-106 距离计算（P0）**
一律使用大圆距离（km）。
*验收*：北京–上海在 1,050–1,100 km 区间；北京–纽约在 10,900–11,000 km 区间。

### 3.2 需求模型（FR-2xx）

**FR-201 总出行需求池（P0）**

```
D_total(A,B) = C · w(scale_A) · w(scale_B) · C_region · conn_A · conn_B
C = 21,455
w = {XL: 1.0000, L: 0.4624, M: 0.2138, S: 0.0989, R: 0.0457}
```

*验收*：
- 北京–上海（XL/XL，国内）单向约 21,455 人次/日（总出行需求）
- 上海–深圳（XL/L）约 9,921
- 上海–合肥类（XL/M）约 4,588
- **距离不进入本公式**：同能级的 1,000 km 与 3,000 km 城市对需求相同

**FR-202 方式分担（P0）**

```
D_air = D_total · sigmoid(c0(d))
c0(d) = −1.119 + (2.442 − (−1.119)) · clamp((d − 600)/1800, 0, 1)
```

*验收*：400 km 航空分担率 24.6%±1%；1,200 km 51.7%±1%；≥ 2,400 km 92.0%±1%。

**FR-203 舱位分层（P0）**

```
b = clamp(0.04 + 0.010·(tier_A + tier_B) + 0.00004·d, 0.04, 0.30)
f = 0.02 当 (tier_A + tier_B ≥ 7 且 d ≥ 4000)，否则 0
经济 = D_air·(1−b−f)；商务 = D_air·b；头等 = D_air·f
```

*验收*：北京–上海商务占比在 10%–12%；经济 + 商务 + 头等 = D_air（误差 < 1e-9）。

**FR-204 枢纽连通度（P1）**

```
conn(i) = min(1.80, 1 + 0.50 · ln(1 + routes_i / 100))
routes_i = 该机场全部在营航段数（所有公司，含经停段）
```

*验收*：0 航段 → 1.000；100 → 1.347；400 → 1.800（封顶）；航段数归零后 conn 回到 1.0。

**FR-205 需求缓存（P1）**
需求池按城市对缓存，连通度变化或航线增删后必须失效重算。
*验收*：新增一条航线后，其两端城市相关 OD 的需求池在下一日结算前已更新。

### 3.3 竞争分配（FR-3xx）

**FR-301 行程产品生成（P0）**
每条航线必须为它实际服务的每个 OD 生成产品，产品携带：航空公司、票价、总旅行时间、
每日班次、是否 HUB、经停次数、换机次数、口碑、以及**实际占用的航段列表 `legs`**。
*验收*：一条 `A→B→C` 的 2 段航线生成 3 个产品（A-B、B-C、A-C），每个产品的 `legs` 分别为
`[段0]`、`[段1]`、`[段0,段1]`。

**FR-302 效用函数（P0）**

```
U = c0(d)
    − c_price · ln(P / P_ref(d, cabin))
    + c_time  · (−T / 10)
    + c_freq  · freq_score
    + c_rep(d) · (rep − 50) / 50
    + c_hub   · hub_flag
    − c_stop  · stop_count
    − c_trans · transfer_count

c_price = 2.182   c_time = 0.25   c_freq = 0.55
c_hub = 0.15      c_stop = 0.335  c_trans = 1.20
c_rep(d) = min(1.20, 0.25 + 0.000075·d)
freq_score = ln(1 + daily_flights) + 0.6 · peak_coverage
```

*验收*：同等条件下，直飞产品份额 > 经停产品 > 换机中转产品；
`c_rep(d)` 在 10,400 km 处为 1.03（短途 300 km 处为 0.273 的 3.8 倍）。

**FR-303 份额计算（P0）**
`share = exp(U) / (1 + Σ exp(U_j))`，外部选项 `U_0 = 0` 代表「不出行/其他交通」。
*验收*：单一运营者、参考票价时份额 = sigmoid(c0(d))，与 FR-202 的分担率一致。

**FR-304 座位上限（P0）**
单个产品的实际承运客流不得超过其可用座位。
*验收*：任何 OD 的承运客流 ≤ 该 OD 的座位供给；全网载客率不得超过 100%。

**FR-305 段容量共享池（P0）**
容量池按「航线 × 航段 × 舱位」建立；**所有压在该航段上的产品共享同一池**，
包括直飞、经停、换机中转。不足时按 `票价 / 占用航段数` 降序分配，被截断的旅客流失。
*验收*：
- 一条 2 段航线的 A-B、B-C、A-C 三个产品之和不得超过任一航段的座位数
- 中转产品的客流必须同时扣减前段与后段的余量
- 构造「中转 + 直达争抢同一航段」的用例，两者客流之和 ≤ 该航段座位

**FR-306 票价（P0）**

```
P(OD, cabin) = P_ref(d_od, cabin) × price_index
P_ref(d) = 3.704 · d^0.7995          （经济舱，人民币元）
舱位系数：经济 1.0 / 商务 2.6 / 头等 4.5
d_od 取 OD 两端的直线距离，不得使用实际航段里程
price_index ∈ [0.50, 1.50]，新航线初始 0.97
```

*验收*：把经停点绕远 40% 后，该 OD 票价不变（误差 < 0.5%），成本上升。

**FR-307 座位门槛（P2，Ver 1.0 未实现）**
某公司在某 OD 某舱位的单日座位 < 30 座时不进入分母，用于阻断「1 座占位」打压对手。
*验收*：构造 5 座座位的高效用产品，其不得影响其他公司的份额。

**FR-308 候选产品上限（P2，Ver 1.0 未实现）**
每 OD 每公司最多 3 个候选产品（1 直飞 + 1 经停 + 1 中转），超标取效用最高者。
*验收*：同一公司对同一 OD 提供 4 个产品时，只有 3 个参与分配。

### 3.4 航线、时刻与周转（FR-4xx）

**FR-401 航线结构（P0）**
航线由 1–3 个航段构成。**Ver 1.0 玩家可创建 1–2 段（0 或 1 个经停点）**，3 段仅规则保留。
*验收*：创建 3 段航线在玩家界面被拒绝并提示「Ver 1.0 不支持」。

**FR-402 经停校验（P0）**
创建经停航线必须同时满足：

| 校验 | 阈值 |
|---|---|
| 总航程 | ≥ 2,000 km |
| 单段航程 | ≥ 300 km |
| 绕行系数 | 总航程 / 两端直线 ≤ 1.40 |
| 防拼远程 | 总航程 ≤ 机型航程 × 1.30 |
| 单段航程 | ≤ 机型航程 × 1.05 |
| 经停点 | 不重复、不与两端同城 |
| 跑道 | 每个机场满足机型跑道等级 |
| 占机 | 往返占机 ≤ 16 h |
| 航段 | 单机每日 ≤ 8 段 |

*验收*：逐条构造反例，每条都必须被拒绝且给出具体原因文案。

**FR-403 时刻占用（P0）**
机场日容量 `slot_cap = 年吞吐量(百万人次) × 16`；每机场每日占用
`2 × 该机场被触及的航段数 × daily_flights`。
*验收*：直飞航线两端各占 2 次/日；2 段航线中间机场占 4 次/日；申请超额时刻被拒绝。

**FR-404 时刻回收（P1，Ver 1.0 未实现）**
60 日滑窗内实际使用率 < 80% 的时刻收回公共池，HUB 保留额度不豁免。
*验收*：某时刻连续 60 日只飞 50% 班次，第 61 日该时刻被收回，原公司重新申请排末位。

**FR-405 机队周转（P0）**

```
单航段占机 = 飞行时间 + 过站时间
过站 = 支线 30 / 窄体 45 / 宽体 90 分钟，飞非 HUB 机场 ×1.15
经停地面 = 同型过站 + 15 分钟
每架飞机每日占机 ≤ 16 h 且航段 ≤ 8 段
```

*验收*：给一架窄体机排 14 班 500 km 航线时必须报错；超限航线当日不执行且不产生产品。

**FR-406 规模上限（P0）**
单公司航段软上限 120 段，超出部分每段 +2% 固定成本。
*验收*：第 121 段的固定成本比第 120 段高 2%。

### 3.5 HUB（FR-5xx）

**FR-501 HUB 数量与门槛（P0）**
每公司 ≤ 3 个 HUB。新增需同时满足：该机场已有 ≥ 2 条本公司航线、吞吐量 ≥ 10 百万人次/年、
本公司在该机场停靠在役飞机 ≥ 3 架、支付一次性开设费（50–300 ¥M）。
年度维持费按能级：XL 0.08、L 0.06、M 0.04、S 0.02、R 0.01 ¥M/日。
关闭后冷却 12 个月。
*验收*：仅满足「2 条航线」时不授予 HUB；开启后每日结算扣除对应维持费。

**FR-502 HUB 收益（P0）**
1. 时刻保留：该机场容量的 30% 优先给 HUB 公司，且受 FR-404 约束
2. 本地偏好：以该机场为端点的 OD 效用 +0.15
3. 成本效应：基地飞机维护与人员 ×0.92，该机场地面服务 ×0.90
*验收*：同一 OD 上，HUB 端点产品份额高于非 HUB 端点产品约 15%。

**FR-503 中转产品生成（P0）**
同一公司在自家 HUB 有两条航线，且前段到达 / 后段出发衔接在 45 分钟–4 小时之间，
生成一个中转产品，最多 1 次换机。`hub_flag = 1`。
*验收*：衔接 30 分钟与 5 小时均不生成；衔接 2 小时生成；同一 OD 每公司只取最短衔接。

### 3.6 机队与成本（FR-6xx）

**FR-601 采购与租赁（P0）**
新机全款或债务融资（贷款上限见 FR-702）；交付周期 60–180 游戏日并占用资金。
租赁：月租 = 目录价 × 0.55%，押金 3 个月，提前退租罚 2 个月。
*验收*：现金不足且无授信时购买失败并提示；租赁机不计折旧只计租金。

**FR-602 折旧与残值（P0）**
自有飞机直线折旧 20 年、残值 10%；机队残值用于市值与授信时**一律取二手市价**
`目录价 × v(age) × 状态系数`，`v(age) = max(0.10, 1 − 0.065·age − 0.0015·age²)`。
*验收*：同一架飞机在「折旧账面值」与「二手市价」两个口径下不得混用于同一指标。

**FR-603 机龄（P0）**
每架飞机每日 `age += 1/360`，影响准点率、取消率、维护费率与口碑。
*验收*：运行 360 日后机龄约 +1.0；机龄 12 年以上取消率开始上升。

**FR-604 日成本项（P0）**

| 成本 | 计算 |
|---|---|
| 燃油 | `2 × daily_flights × 座位 × 每座百公里油耗 × 里程/100 × 5.0 元/kg ÷ 1e6` |
| 起降费 | `2 × daily_flights × 0.008 ¥M × (MTOW/70)^0.7`（每航段） |
| 导航费 | `2 × daily_flights × 航段里程 × 1.0e-5 ¥M/km × (MTOW/70)` |
| 维护 | `2 × daily_flights × (航段里程/速度) × 维护费率 × 1.4` |
| 折旧 | `目录价 × 0.9 / (20 × 360)` 每机每日 |
| 租金 | `目录价 × 0.0055 / 30` 每机每日 |
| 人员 | `0.15 + 0.05 × 飞机数 + 0.01 × 航段数`（¥M/日） |
| 分销 | 收入 × 10% |
| 地面 | `0.00012 ¥M × 客流` |
| HUB | 见 FR-501 |
| 利息 | `负债 × 年利率 / 360` |
| 闲置 | `0.02 ¥M/日 × 闲置飞机数` |

*验收*：各项成本可单独显示在结算明细中；关停全部航线时成本仅剩折旧、租金、人员、HUB、利息、闲置。

### 3.7 财务（FR-7xx）

**FR-701 日结算（P0）**
每日一次，输出收入、9 项成本、EBITDA、现金余额、载客率。
*验收*：`revenue − cost = Δ现金`（误差 < 0.01 ¥M）；EBITDA 与净利的差额等于折旧。

**FR-702 贷款与杠杆（P0）**

```
授信上限 = min(机队残值 × 0.6 + max(0, 12月EBITDA) × 3, 权益 × 2.0)
年利率 = clamp(6% + 负债率 × 6%, 6%, 12%)
```

*验收*：亏损公司的授信不得高于其机队残值 × 0.6（即亏损不能增加授信）；
负债/权益超过 2.0 后新增贷款被拒。

**FR-703 破产判定（P0）**
现金 < 0 且授信为 0 → `资金链断裂`；负债 > 3 × 权益 → `资不抵债`。
*验收*：两种原因都能在压力场景下被触发并记录到公司状态。

**FR-704 破产清算（P0）**
航线与时刻回公共池；机队按 70% 二手市价流入二手市场；现金归零；不复活。
*验收*：破产后该公司的 OD 上不再有其产品，其他公司份额在次日上升。

**FR-705 市值与排名（P0）**

```
市值 = EBITDA年化 × m + 机队残值 + 现金 − 负债
m = clamp(8 − 4 × 净负债率, 4, 8)，净负债率 = 负债 / (负债 + 权益)
```

*验收*：同等 EBITDA 下，高杠杆公司市值低于低杠杆公司。

**FR-706 月报表（P1）**
每月输出损益表、资产负债表、运营 KPI（载客率、准点率、航线数、机队、市场份额）。
*验收*：连续 12 个月的月报表可回溯，且与日结算累计一致。

### 3.8 口碑（FR-8xx）

**FR-801 航线运营指标（P0）**

```
on_time     = clamp(0.985 − 0.005 × 机龄, 0.80, 0.99)
cancel_rate = clamp(0.005 + 0.003 × max(0, 机龄 − 12), 0, 0.12)
可用运力 = 名义座位 × (1 − cancel_rate)
```

*验收*：机龄 0 时准点 98.5%、取消 0.5%；机龄 20 时取消率 2.9%。

**FR-802 口碑目标值（P0）**

```
comfort_w = 10 + 20 × clamp((航距 − 1500)/5000, 0, 1)
rep_target = 50 + 25·准点分 + 10·机龄分 + comfort_w·舒适度 + 5·HUB覆盖 − 15·取消率
```

*验收*：同一机型在 3,000 km 与 8,000 km 航线上贡献的口碑不同，后者更高权重。

**FR-803 口碑惯性（P0）**
`rep = clamp(rep + (rep_target − rep) × 0.05, 0, 100)`。
*验收*：新航线口碑从公司当前值起步，约 60 日收敛到目标值 95%。

**FR-804 客流加权（P0）**
公司口碑 = Σ(航线口碑 × 该航线客流) / Σ客流。
*验收*：高客流航线的口碑变化对总口碑影响显著大于低客流航线。

### 3.9 AI（FR-9xx）

**FR-901 决策周期（P0）**
每 7 游戏日决策一次；AI 与玩家使用同一套规则与参数，不得有特权。
*验收*：把 AI 换成玩家操作，同一初始条件下结果可比较。

**FR-902 关线（P0）**
连续 2 个决策周期载客率 < 0.40 → 关线；**必须保留最后一条航线**。
*验收*：不会出现「0 航线但仍在运营」的公司。

**FR-903 定价（P0）**
在 `[0.90, 1.40]` 的涨价倍数中枚举，比较 `(票价 − 单位变动成本) × 客流` 取最优；
目标指数向 `base × 最优倍数` 平滑移动（60%），限制在 `[0.50, 1.50]`。
**允许售罄**，不以载客率为目标。
*验收*：售罄航线的价格指数应高于未售罄航线；不得出现价格在两个周期之间来回震荡。

**FR-904 加密班次（P1）**
载客率 > 0.85 时尝试加班次；运力不足则买机，买不起则回滚。
*验收*：加班次后机队占机不得超过 16 h/机。

**FR-905 扩张（P0）**
只从自有 HUB 或已服务城市延伸；候选 OD 需需求 ≥ 150 人次/日、距离 300–6,000 km、
两端机场时刻充足；每次决策最多开 2 条。
*验收*：AI 不会从非枢纽城市凭空开出航线。

**FR-906 经停（P1）**
有闲置运力（占机 < 85%）时，尝试把一条直飞航线延伸为 2 段经停航线；
每端点最多评估 3 个候选。**AI 不生成 3 段航线**。
*验收*：AI 产生的经停航线 100% 为 2 段。

**FR-907 收缩（P0）**
连续 60 日 EBITDA < 0 → 关最差航线 + 卖一架最旧飞机；连续 30 日亏损时暂停扩张。
*验收*：亏损公司在 60 日后机队数量下降。

**FR-908 破产（P0）**
见 FR-703/704。
*验收*：压力成本系数 ≥ 1.3 时出现 10% 以上公司破产。

### 3.10 玩家操作与信息边界（FR-10xx）

**FR-1001 玩家操作集（P0）**

| 类别 | 操作 |
|---|---|
| 战略 | 选/开/关 HUB；开/关航线；设置经停点；调班次；设价格指数；设三舱座位 |
| 机队 | 新机下单、买二手、租机、退租、卖机 |
| 财务 | 申请贷款、提前还贷 |
| 时间 | 暂停 / 1× / 4× / 16× |
| 系统 | 存档 / 读档 / 新游戏 |

*验收*：玩家可完整执行上表任一操作，且每项操作都有失败原因反馈。

**FR-1002 信息边界（P0）**
- 可见：所有公司公开航线、班次、市场份额、价格指数与各 OD 参考票价（经济/商务）、排名
- 可见：本人每个时刻格的使用率与距被收回的剩余天数
- 不可见：对手成本、收入、利润等财务数据，对手内部参数与未来决策
*验收*：UI 上可查看对手航线的价格指数与各 OD 票价，但无法获取其成本、收入或利润。

### 3.11 目标与评价（FR-11xx）

**FR-1101 沙盒模式（P0）**：无终点，随时存档退出。
**FR-1102 可选目标（P1）**

| 目标 | 条件 |
|---|---|
| 市值进前三 | 10 游戏年内市值排名 ≤ 3 |
| 区域霸主 | 某区域内市场份额 ≥ 35% |
| 高质高效 | 连续 24 个月 EBITDA 率 ≥ 15% 且准点率 ≥ 85% |
| 网络扩张 | 航段数 ≥ 100 且平均载客率 ≥ 75% |

**FR-1103 评价（P1）**：达成目标结算 A–E 评级；未达成不打分。
*验收*：四个目标互不冲突，可同时追踪。

### 3.12 系统（FR-12xx）

**FR-1201 存档（P0）**：本地单存档 + 自动存档（每 30 游戏日），单档 < 5 MB，可导出。
**FR-1202 随机种子（P0）**：种子入档，同一存档同日重放结果一致。
*验收*：读档后重放同一日，所有随机结果完全相同。
**FR-1203 参数外置（P0）**：机场库、机型库、系数表外置，修改后重启生效。
**FR-1204 调试模式（P2）**：参数面板与结算明细开关，正式版默认隐藏。

## 4. 非功能需求

**NFR-1 性能（P0）**
300 机场 + 51 家公司 + 1,000 条航线的日结算 < 100 ms；1× 速度下不得掉帧。
*验收*：50 家 AI 跑 720 游戏日的总耗时 < 5 分钟（参考实现约 48 秒）。

**NFR-2 计算量控制（P0）**
只对「至少有一家运营」的 OD 做分配；若 OD 覆盖 > 15,000 个，按总座位 × 预估需求降序保留前 15,000 个。

**NFR-3 可测试性（P0）**
需求模型中每个系数必须能从外部文件加载，且提供不依赖 UI 的无头模拟入口，可批量跑参数扫描。
*验收*：可在命令行指定天数、对手数、起始资金、成本系数并输出报告。

**NFR-4 平衡性验收基线（P0）**

| 指标 | 目标区间 |
|---|---|
| 全网平均载客率 | 75% – 90% |
| EBITDA 率 | 15% – 25% |
| 破产比例（50 家 × 720 日） | 2 – 5 家 |
| 航线中位载客率 | 不强制（允许售罄） |

**NFR-5 本地化（P1）**：简体中文；金额单位 ¥M；数字千分位。

## 10. 交付判定

Ver 1.0 视为可交付，需同时满足：

1. 第 8 节中标 ⚠ 的 **P0** 项全部关闭（当前无 P0 缺口）
2. NFR-4 的三项指标进入目标区间（或由难度设置明确覆盖）
3. 第 6 节的校准基线保持达标
4. 附录 F 中的 P0 经停问题全部关闭（已达成 F-01/F-02/F-03）
5. `sim/selftest.py` 全部通过（当前 19 / 19）
6. 前端可完成一次完整操作闭环：开线 → 调价 → 观察载客率与利润 → 关线

**已交付的架构决策**：前后端分离，后端本地跑权威模拟，浏览器通过 HTTP API 交互；
明确放弃多人对战，仅单机 AI 对战。该决策使「指令确定性排序」「服务端权威校验」
「反作弊」三类多人需求全部移出范围。
